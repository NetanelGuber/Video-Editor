# Session 14 — Nested sequences and multicamera

Complete and user-accepted on 2026-10-08 in version 0.14.0, schema 6. The user reported testing and authorized completion; see the [acceptance record](../evidence/session-14/manual-acceptance.json). Nested sequences remain editable children in the same project. Optional multicamera groups support two through four cameras with frame-exact hold switches and fixed reference audio. Existing schema 1–5 projects migrate without acquiring either feature. Automated results are collected in [Session 14 evidence](../evidence/session-14/verification.json).

## Native controls

The timeline's sequence selector opens any sequence. **New sequence…** creates an empty sequence with the current sequence's frame rate and dimensions. Edit the child, open the intended parent in the selector, then choose **Nest sequence…**. The default inserts nested video and a separate nested audio clip at the playhead. These clips have independent editing controls. Select a nested clip and choose **Open child** to edit the original; every instance uses its current content. Sequence creation, insertion, navigation, trim, split, move and camera changes participate in the existing undo history. Source media remains untouched.

Choose **New multicamera…**, select two through four distinct imported video streams, and enter source offsets to align the same event at sequence start. Offset entry follows **View → Time display** in seconds or sequence frames. The shortest remaining camera defines the new sequence's length. Camera 1's first audio stream supplies continuous reference audio when it covers the interval; otherwise the group starts without an audio track. This is manual synchronization; waveform/timecode/automatic synchronization is outside this slice.

**Camera overview** displays the synchronized cameras in numbered tiles. **Camera 1** through **Camera 4** insert a switch at the current playhead. The switch holds until the next saved switch; inserting at an existing switch replaces it. The timeline draws camera switch lines. Live switches keep the warm camera decoders and audio clock running. Turn off **Camera overview** to see the edited output. Overview is preview state and never changes export. **Ungroup cameras** retains camera tracks and media while removing the switching program; undo restores the group. Ungroup before changing camera lengths, disabling/removing camera tracks or applying speed changes.

Offline camera clips appear in the bin and timeline, including media referenced through nested clips. Decoder errors appear in the viewer's statistics. Export preflight reports missing camera media even when that camera is not currently selected. Existing relinking updates the media record for all uses.

## Mapping and limits

Nested clips use `sequenceId` instead of a media/title reference. Their source ticks are child sequence frame indices. Parent and child must have the same reduced frame rate, and the nested interval plays at 1×: `childFrame = parentFrame - clip.startFrame + clip.sourceInTicks`. Both intervals are half-open. Trimming advances the child in-point; splitting preserves the right child's source position; moving changes only parent placement. Source-range validation prevents a shortened child from invalidating existing instances. Direct/indirect cycles are rejected across enabled and disabled tracks. The model supports 128 sequences and eight nesting levels; compilation bounds expansion to 512 sequence instances and 4096 source leaves, with at most eight concurrent video decoders.

Child video effects and titles compose inside the child before the parent applies its clip effects. Child audio mapping, fades, automation, buses and pitch-preserving speed processing remain intact; parent audio gains, fades and automation multiply them. Mixing sums leaf sources before the single final master clamp, so nested audio does not introduce an intermediate clipped submix. Source sample offsets use the difference between independently rounded parent-start and child-in 48 kHz sample positions. Deep nesting collapses to one decode relay per leaf; each relay and underlying decoder has a bounded queue. This can use twice the configured leaf queue budget and does not establish a global peak-memory guarantee.

The four-camera profile uses up to 640×360 decode per camera, a viewer up to 720p, and 30 fps presentation. Camera overview combines the four tiles; the selected camera is scaled to the viewer. One/two-camera preview keeps the normal selected quality. If a camera falls behind, synchronized buffering holds the viewer and pauses the audio clock until the cameras reach a common position. Final export decodes originals at full resolution. Raising quality controls cannot bypass the three/four-camera decode cap.
