# Session 15 — encoder-aware export and compatibility

Version 0.15.1, schema 9. Desktop playback is prioritized. The initial [Session 15 concept](session-15-concept.md) and the user's expanded [every-encoder concept](session-15-encoder-concept.md) were completed before their corresponding implementation changes. The 2026-10-08 follow-up adds custom-choice availability filtering and automatic export frame-rate selection; its Release build succeeded. Workspace organization and Simple/Advanced tabs remain Sessions 15.1 and 15.2.

## Choosing an export

Open **File → Export sequence…**. **Playback target** retains Desktop MP4, Desktop Matroska, Broad MP4 (up to 1080p/30) and HEVC MP4 (up to 4K/60), with optional AAC-LC 48 kHz stereo. These targets use 8-bit SDR BT.709; Broad MP4 constrains software H.264 High Level 4.1 and a 20 Mb/s VBV ceiling. HEVC MP4 uses Main and hvc1. Physical player compatibility remains unverified.

**Video encoder** and its custom-mode list show only encoders that pass the bounded availability probe for the current dimensions, frame rate and audio context. The inventory still records all names in the loaded FFmpeg build, including probe failures with reasons. Selecting a listed name switches to **Custom encoder / container**, chooses a compatible container and automatic pixel format, clears the previous encoder's overrides and supplies that encoder's native speed/quality defaults. Container choices require codec/muxer support. Manual **Pixel format** choices are limited to formats the editor can create through CPU conversion; **Automatic** may retain a supported hardware pixel format. The custom **Audio encoder** and **Native options** controls are configurable. Custom dimensions are 1–4096 pixels per edge and rates are positive reduced fractions up to 240 fps; codecs can impose additional requirements. The compositor outputs an opaque 8-bit SDR image; 10/12/16-bit pixel formats convert the existing 8-bit compositor output and do not create HDR or extra source precision.

When output FPS has not been manually changed, it defaults to the lowest valid frame rate among imported video streams, falling back to the sequence rate when there are no imported videos. Manually changing the output rate preserves that override.

**Encoding speed** uses the selected encoder's native option names and values. x264/x265 expose their ten presets, AMF exposes its actual quality constants, NVENC its presets and VP9/AV1 their own numeric speed choices. The bundled HEVC AMF options include a newer high_quality constant in addition to speed/balanced/quality; each configuration must pass the local driver probe. **Quality / rate control** offers Native quality, Encoder default / native overrides, and Target bitrate in kbit/s. The quality label/range changes with the selected encoder; equal numbers do not imply equal visual quality. Common examples are HEVC AMF QP 0–51, AV1 AMF QP 0–255 and VP9 CRF 0–63. Fractional CRF, WebP quality and JPEG XL distance use decimal inputs; integer QP controls reject fractions. WebP compression speed is separate from its image-type preset. Theora and WebP quality increase with higher values, while JPEG XL distance and common quantizers improve with lower values. Encoders without a recognized primary quality/speed control disable that field; their native options remain accessible. Lossless/image/fixed-rate codecs without a primary bitrate control disable that choice.

The **Native options** table exposes writable private video encoding AVOptions and common codec-context controls, with defaults, ranges, enum choices and FFmpeg help in tooltips. Leave an override blank for defaults. To override a Speed/Quality-owned option directly, first select Encoder default for that control. Duplicate/invalid/unavailable overrides immediately block export with a specific reason. Native overrides require Custom so they cannot invalidate the profile/level guarantees of fixed targets. Complex string options retain FFmpeg syntax. Options can depend on other options and hardware capabilities, so the exact encode/mux probe remains decisive. Some codec options need extra inputs or stream structures which a single composited video export cannot supply; these configurations fail with a reason rather than disappearing from the inventory.

Custom output supports the shared 48 kHz stereo mix with AAC, Opus, FLAC, MP3, AC-3 or PCM when compatible with the container. Video-only containers require **Include audio** off. Host sample formats adapt through libswresample; the mix and timeline sample count remain shared with preview. Selecting another container preserves conflicting saved audio choices visibly until resolved. Turn Include audio off and on to repair a saved sample-rate/channel conflict.

Software/Automatic policies remain available for fixed playback targets. Automatic uses encoder defaults to avoid translating CPU speed labels or pretending quality scales are interchangeable. It tries AMD, NVIDIA and Intel, then software; explicit encoder names never silently fall back. Status identifies the actual encoder and fallback reasons. Selecting a fixed target resets its codec/container/audio/encoder defaults while preserving dimensions/rate. Opening saved conflicting settings preserves them and blocks export; reselecting a target or encoder explicitly repairs its tuple.

## Runtime behavior and persistence

All compiled encoders are catalogued and probed, but the custom encoder selector now hides candidates that fail the bounded availability scan for the current settings. Selection still does not establish usability: the worker runs a disposable **ExportCapabilityProbe.exe** beside **VideoEditor.exe** against the exact dimensions/rate/pixel/options/audio/container configuration. It encodes three frames, optional audio, flushes packets and writes a trailer. Device creation is separate. Encoder/device helpers have 15/4-second deadlines and are killed on cancellation. Driver calls never run on the GUI thread. **Refresh capabilities** cancels old work and retries; **Capability details…** shows inventory, controls and exact probe diagnostics. A 200 ms debounce and generation/configuration ownership checks prevent stale results from enabling Export. Configuration identity includes the requested encoder even when two encoders have the same displayed defaults. Successful probes also retain backend warnings about ignored or adjusted settings and show them with the validated encoder.

The probe and production worker share encoder configuration. Host pixels use swscale; palette encoders use a defined 3:3:2 RGB palette; hardware-only advertised input uses device/frame contexts and upload when supported. Unsupported conversion, driver, dimensions, special stream constraints and muxer failures block export with a reason. Some muxers report unknown codec compatibility; the actual header/packet/trailer probe resolves that uncertainty. Image codecs also offer image2pipe as one file containing encoded image packets; this stream carries no playback timing/audio, so a player may assume its own frame rate. Direct3D 12 / Media Foundation defaults use MPEG-TS for H.264/HEVC and IVF for AV1 to accommodate in-band configuration; selecting a different container requires its exact probe to succeed. Exact settings are tested again immediately before every production export. Output uses QSaveFile atomic publication; cancellation/failure preserves the destination and originals.

Schema 9 stores whether export frame rate is a manual override. Schema 8 introduced fractional quality and stores qualityMode, audioEncoder and a bounded native encoderOptions map, alongside the Session 15 compatibilityProfile/videoEncoder/pixelFormat choices. Schemas 1–8 migrate; schema 7 hardware speed labels migrate to the native value previously used. Runtime capability snapshots are rediscovered on each computer and never serialized. Unknown saved encoder/option choices survive persistence and warn at export time. Export settings retain transactional undo/redo.

## Verification

Run `./scripts/Build.ps1`, `./scripts/Test-Application.ps1`, then `./scripts/Collect-Session15Evidence.ps1`. Keep the Release folder together with helper and DLLs. The full regression now includes **export-encoder-catalog**: it checks that every compiled video encoder is in the production selector, introspects all descriptors, validates native defaults and records a bounded representative exact configuration probe for every encoder. Catalog probes use a six-second deadline and classify the attempted settings, not every possible configuration or machine.

Production exports cover x264/x265, VP9, AOM/SVT AV1, ProRes, FFV1, HuffYUV, MPEG-4, MJPEG, PNG, GIF, BMP image streams, rawvideo, Theora, six audio encoders and every usable target-PC common hardware encoder. Independent FFprobe inspection and complete FFmpeg decoding check codec, dimensions, frame count and audio inclusion. Tests also cover native scales/speeds, disabled irrelevant fields, invalid native overrides, schema-7 migration, exact schema-8 persistence/undo and production UI adaptation. Existing suites verify fixed profiles, source content, effects, timing, audio, 4K, cancellation and originals.

Collected evidence lives in [verification.json](../evidence/session-15/verification.json), [encoder-catalog-result.json](../evidence/session-15/encoder-catalog-result.json), [capabilities-result.json](../evidence/session-15/capabilities-result.json) and the samples folder. Final counts and host results are recorded after regression.

## Limits and sources

No computer use or human visual acceptance is claimed. Physical playback devices, Windows visual scaling, subjective quality/AV sync and long hardware stability remain unverified. A failed representative probe may succeed with other dimensions, bitrate, native options, container or driver; it does not establish global unavailability. Advanced settings such as multi-pass external statistics or auxiliary input streams may require workflows beyond this single-pass composited export. MP4 fast-start packaging and distribution/license review remain future work.

Implementation continuously consulted official [AVOptions](https://ffmpeg.org/doxygen/trunk/group__avoptions.html), [encoder APIs](https://ffmpeg.org/doxygen/trunk/group__lavc__core.html), [codec options](https://ffmpeg.org/ffmpeg-codecs.html), [muxing](https://ffmpeg.org/doxygen/trunk/group__lavf__encoding.html), [formats](https://ffmpeg.org/ffmpeg-formats.html), [hardware frames/transfers](https://ffmpeg.org/doxygen/trunk/hwcontext_8h.html), [pixel descriptors](https://ffmpeg.org/doxygen/trunk/pixdesc_8h.html) and [licensing](https://ffmpeg.org/legal.html), plus adapter sources and bundled option help. The pinned FFmpeg 9.0.2 headers/queries take precedence over online trunk documentation.

Baseline verification for the schema-8 implementation on 2026-10-08: all 15 suites passed in 140.72 seconds, including 124 profile/capability checks and 763 every-encoder checks. All 140 compiled video encoders were catalogued and classified at representative settings: 101 configurations passed and 39 failed with reasons. These are configuration-specific outcomes; special dimensions/options/containers or other drivers can change them. Forty representative outputs passed independent metadata inspection and complete decoding, including 33 catalog outputs covering AMD AMF H.264/HEVC/AV1, Direct3D 12 H.264/HEVC/AV1, H.264 Media Foundation, fractional CRF, 10-bit HEVC/FFV1, native ProRes profile and all six custom audio choices. All 30 originals retained inventoried size/mtime. The 2026-10-08 schema-9 follow-up Release build succeeded. No automated suite or human visual acceptance was run for that follow-up.
